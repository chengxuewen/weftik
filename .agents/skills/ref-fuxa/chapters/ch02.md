## 2.2 Backend: Node.js + Express

- **Runtime**: Node.js 18 LTS (recommended) / Node.js 20+
- **WebSocket**: Backend pushes real-time data to frontend (tag value changes, alarm events) via socket.io
- **REST API**: Complete RESTful API for external system integration
- **Process modes**: Standard (single process) and Daemon (background daemon for embedded/headless)
- **Storage**: Config = SQLite; History = SQLite or InfluxDB; Project files = filesystem (JSON format)

## 2.3 Frontend: Angular SPA

- **Framework**: Angular (version unspecified, likely 15+)
- **SVG Editor**: Browser-native SVG drag-and-drop editor — FUXA's most unique component
- **Real-time update**: WebSocket receives tag data changes, millisecond-level screen updates
- **Responsive design**: Mobile browser support (not a dedicated mobile app)

## 2.5 Protocol Support

| Protocol | Mode | Implementation | Notes |
|----------|------|---------------|-------|
| Modbus RTU | Serial (RS232/RS485) | node-modbus / serialport | RTU mode |
| Modbus TCP | TCP | node-modbus | TCP mode |
| OPC UA | TCP | node-opcua | Subscription mode |
| MQTT | TCP | mqtt.js | Publish/subscribe |
| Siemens S7 | TCP | node-snap7 / nodes7 | Direct S7-300/400/1200/1500 |
| BACnet | UDP | node-bacnet | Building automation |
| EtherNet/IP | TCP/UDP | Custom driver | Allen-Bradley PLC |
| WebAPI | HTTP/HTTPS | axios/fetch | REST API data source |

## 2.6 Device Data Flow Model

```
┌─────────────┐    ┌──────────────┐    ┌─────────────┐
│ Physical Device│ → │ Protocol Adapter│ → │ Tag Engine    │
│ (PLC/Sensor) │    │ (Device Driver) │    │             │
└─────────────┘    └──────────────┘    └──────┬──────┘
                                               │
               ┌───────────────────────────────┼──────────────────┐
               ↓                                ↓                  ↓
        ┌────────────┐                 ┌─────────────┐    ┌─────────────┐
        │ WebSocket  │                 │ Alarm Engine│    │ History     │
        │ → Frontend │                 │             │    │ (InfluxDB)  │
        └────────────┘                 └─────────────┘    └─────────────┘
```

**Data acquisition modes**:
- **Polling**: Modbus, S7 — periodic read cycles
- **Subscription**: OPC UA — data change events pushed automatically
- **Event-driven**: MQTT — message-based event model

## 2.7 Plugin Architecture for Protocol Adapters

Each adapter implements a unified interface (connect, disconnect, read, write). Adding a new protocol only requires implementing the same interface. The adapters are independent modules in `protocols/`.

## 2.8 Weftik Architecture Mapping

| FUXA Layer | Weftik Corresponding |
|------------|----------------------|
| Node.js + Express backend | Rust core (Tauri backend for Studio, Runtime for edge) |
| Angular SPA frontend | Tauri + React + TypeScript (D21) |
| WebSocket real-time channel | HAL StreamChannel or WebSocket bridge |
| Protocol adapter plugins | HAL Driver trait plugins (independent crates) |
| SQLite + InfluxDB | Config storage (YAML→FlatBuffers) + pluggable TSDB |
| Tag Engine | HAL Signal registry |
| Alarm Manager | Runtime alarm pipeline |
